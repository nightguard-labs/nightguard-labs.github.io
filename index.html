The problem

The model is twice the size of the RAM

Model on SSD
64 GB
Mac's RAM
32 GB
Expert cache in RAM
13.3 GB

Mixture-of-experts models only use a small slice of their experts for each token. So the whole model lives on the SSD, and the experts that actually get used stay cached in RAM. Reads run through 8 parallel lanes, plus a separate relay for rarely used experts so they never block the common ones. In this setup, 74–80% of expert reads come straight from RAM.

I approached it like a network engineer: layers with one job each, one protocol between parts, separate links so traffic never blocks, and escalation when a layer can't handle something.

The design

A four-layer brain stack

Each layer only gets a task if the one below it fails its own checks. Most tasks should never reach the slow giants.

What worked, what didn't
Worked

The shrink kept quality. I profiled 200k tokens of my own code, kept the experts covering 90% of the router's picks at 4-bit, and pushed the rest to 2-bit. Loss on held-out code rose only 0.66%, and the common-expert set dropped from 63.7 GB to 41 GB.

Didn't

The shrunk model wasn't faster. Mixed 4-bit and 2-bit layers sent every pick through both precision paths. The fix converts 2-bit experts to 4-bit exactly as they come off the SSD: 2-bit levels sit on the 4-bit grid at a ×4 step, and power-of-two scales keep bf16 exact. Verified at 0.00000% difference. Speed race pending.

Worked

Swift doubled the 9B's speed compared with the Python path. Whether 4-bit costs it quality is still open.

Caught

The self-checking loop can be fooled. On one exam task the model's own checks said "solved" and the hidden tests said no. That's why every task gets hidden tests, and false wins never reach training.
